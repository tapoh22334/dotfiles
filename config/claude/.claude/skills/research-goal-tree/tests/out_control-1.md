# 計画書(最初に書く文書): C は A・B と連続に移り合えるか

## 0. 現状の評価

- 「C は別の成分だろう」は印象にとどまる。分断を示す量が無いので、現時点で言えるのは「C から A への経路は見つかっていない」までである。
- 5 手法が同じ「重心の余裕 0.01 の境界」で止まったことは、経路が無い証拠にならない。次の 3 通りが区別できていない。
  1. 本当に分断されている。
  2. 余裕 0.01 という閾値のせいで細い通路が塞がっている。
  3. 5 手法とも「A に近づく」という同じ目的で動いており、同じ袋小路に落ちている。
- 800 点のグラフで C が離れていることも、分断の証拠にならない。標本が疎ければ、つながった空間でも成分は割れる。辺を張る距離の設定にも依存する。
- A-B の「つながった」は 300 区間の格子点での確認である。格子の間で制約が破れていないことは、まだ示していない。

## 1. オーナーの問いへの答え方

結論は次の 3 種類のどれかで返す。どれにもならなければ「未決」と報告し、分かった範囲を書く。

| 結論 | 必要な根拠 |
|---|---|
| つながる | C から A までの経路を 1 本示し、区間の全域で制約を満たすことを検証したもの |
| 移り合えない | 連続な量 f を示す。f は実行可能集合の上で A・B 側と C 側の値を分け、境界を越えると f が必ず制約を破る。または、緩和した問題でも分断を証明する |
| 未決 | 上のどちらも得られなかった。試した範囲と、分かったことを書く |

「手法を 10 通り試して全部だめだった」は、分断の根拠として報告しない。

## 2. 12 時間の配分

### 工程 1(0〜2 時間): 既存の結果の確かめ直し

1. A-B の経路を、区間内の制約違反を排除できる形で再検証する。制約関数の Lipschitz 定数か区間演算で、各区間の最小余裕に下限を付ける。
2. 5 手法が止まった点を集め、同じ点かどうかを見る。以下を記録する。
   - 点どうしの距離。
   - 各点で効いている制約。
   - 各点が「A への距離」の局所最小かどうか(KKT 条件)。
3. 800 点のグラフの辺の基準を 3 通りに変え、C の成分が離れたままか見る。

### 工程 2(2〜5 時間): 余裕の掃引

余裕 m を 0.01 から 0 の側へ段階的に下げ、C-A の接続を各 m で調べる。

- ある m* で急につながるなら、2 の仮説(閾値による閉塞)が支持される。報告は「余裕 m* 以下でつながる。0.01 では閉塞」とする。
- m = 0 でも、さらに負の側まで緩めても割れたままなら、分断の可能性が上がる。

### 工程 3(3〜8 時間): 目的を変えた探索

工程 2 と並行して、A への距離を下げる以外の方法で経路を探す。

- 目的を持たない探索木(RRT-Connect など)を、C と A の両側から伸ばす。
- C から A ではなく、A・B 側から C へ向かう方向でも探す。
- 止まった点から、制約の接空間に沿って余裕を増やす方向へ動き、境界から離れて再開する。
- A・B から出発して「C に近づく」ことが原理的に止まる境界を調べる。

### 工程 4(5〜10 時間): 分断を示す量の探索

分断が疑わしいときだけ行う。工程 2 と 3 の結果を見て、着手するか決める。

- 止まった点で効いている制約を調べ、その制約を連続に保つ限り変わらない量(部品どうしの順序、通過する側など)が無いかを探す。
- 見つかった量は、A・B 側の標本と C 側の標本の両方で、全点について計算して値を比べる。
- 緩和した問題(制約を弱めたもの)でも分断が証明できるなら、それが分断の根拠になる。
- 量の候補は、実際に A・B と C で値が違うことを確認するまで「候補」と書く。

### 工程 5(10〜12 時間): 報告

骨子は 4 節に置く。残り時間が 1 時間を切ったら探索を止め、報告に回る。

## 3. 事前に決める中止条件

- 工程 2 で全ての m について経路が得られず、かつ工程 3 でも新しい到達点が出ないとき、追加の試行はしない。工程 4 に進むか、「未決」として報告する。
- 試行を足して基準を緩めることはしない。基準を動かす場合は、動かした理由と時刻を記録に残す。
- 12 時間のうち、工程 4 に使うのは最大 5 時間とする。
- 計算資源の使い切りは目的にしない。結論が出た時点で止めてよい。

## 4. 報告の骨子

1. 結論(つながる / 移り合えない / 未決)を冒頭に 1 文で書く。
2. 結論を支える根拠。経路の検証結果か、分断を示す量とその検証のどちらか。
3. 前提の確認結果。A-B の再検証と、余裕の掃引の表。
4. 否定された仮説。たとえば「閾値による閉塞ではなかった」。
5. 試して効かなかった方法と、その理由の推測(推測と明記する)。
6. 残った不確かさと、オーナーだけが決められること(余裕 0.01 が仕様かどうかなど)。

## 5. 最初に確認する、オーナーにしか決められない点

余裕 0.01 は、設計上の要件か、安全側に置いた値かを確認する。要件でなければ、工程 2 の結果が問いに直接答える。12 時間は待たずに進める。確認の回答は報告に記載する。
