# research-goal-tree — 目的の木と、木だけを読む審査役

研究を細分化すると、各段の結果が正しくても、上位の目的に答えているかを誰も確かめなくなる。書いた本人は自分の飛躍が見えない(#637 では、本人が書いた木に、独立の審査役が 11 件の不備を見つけた。うち 1 件は根の問いを満たせなくする致命的なもので、2 件は本人の記憶違いだった)。

そこで、研究の論理を **1 つのファイルの木** に置き、**木だけを読む別の審査役** に不備を指摘させる。報告はこの木から組み立てる。説明責任は木を管理する指揮役が持ち、審査役には移らない。

## 木の形

研究の作業場所(リポジトリの research/ など)に 1 ファイル置く。節点ごとに次の欄を必ず書く。

| 欄 | 書くこと |
|---|---|
| 目的 | この節点で何を明らかにするか |
| 親への寄与 | なぜ親の目的にこれが要るか(根では、問いの持ち主の言葉を引用する) |
| 達成の条件 | 何が観測されたら達成か。**事前に書いたか、事後に補ったかを明記する** |
| 方法の選択 | 選んだ方法・捨てた方法・理由。方法ごとに「答えが出うるか」(下記) |
| 結果と親への帰結 | 親の問いについて何を言え、何を言えないか |
| 状態・出典 | 達成/未達(進行中)/未達(停止)/不要。根拠のファイルと節 |

根には、**打ち切りの条件と報告の形式**(期限、未達のときに何を報告するか)も書く。末尾に「審査の記録」の表(番号・節点・重さ・指摘・対応)を置く。

## 手順

1. **書く。** 既存の作業から書き起こすときは、記憶や要約からではなく、出典を開いて書く。根の目的が「すべての〜」なら、その集合を列挙する節点を置く。
2. **方法の事前検査。** 計算や実装を始める前に、方法の行に次の 3 つを書く。書けない方法は始めない。
   - 成功したら、どの達成の条件を満たすか。
   - 失敗したら何が分かるか。
   - 表にある過去の失敗と、同じ理由で止まらないと言える根拠。止める条件(時間・数値)も。
3. **審査役に依頼する。** 節点を作ったとき、結果が出たとき、報告の前に、下の依頼文で新しい文脈のエージェントに依頼する。自分の要約は渡さない。
4. **指摘を確かめてから採否を決める。** 審査役の事実の主張は出典で確かめる(審査役も誤る)。全件を「審査の記録」に、採否と理由つきで残す。
5. **報告は木から組み立てる。** 木にない主張を報告に足さない。

## 審査役への依頼文(そのまま渡す)

> あなたは研究の「論理の審査役」で、研究に参加していない。次のファイルだけを読み、論理の不備を探す:`<木のパス>`。確かめるのは 3 点だけ。① 子をすべて達成すれば親を満たせるか(漏れ・親に寄与しない節点)。② 各節点の欄が埋まっているか、事後に補った達成の条件が結果に合わせて甘くなっていないか。③ 結果から親への帰結が飛躍していないか(言えないことを言う・言えることを落とす)。疑わしい主張は、木が挙げる出典を読んで確かめてよい。ファイルは書き換えない。報告は日本語で、不備の一覧(節点/致命・重要・軽微/何が不備か/どう直すか)、最も重大な 1 件とその理由、不備がないと判断した観点を書く。無理に指摘を作らない。

## よくある不備(#637 の審査で実際に出たもの)

| 不備 | 見分け方 |
|---|---|
| 「すべての X」を、選んだ一部に断りなく置き換える | 根の条件の集合を列挙する節点がない |
| 別の空間・別の条件での結果を、進捗として数える | 結果の欄の「どの空間で」が親と違う |
| 前提つきの定理を、無条件の結果として下位で使う | 前提の記号が引用先で消えている |
| 接続(存在)と分断(全称)など、確かさの水準が違うことを明記していない | 片方だけに区間演算・証明を求めている |
| 同じ理由で止まる方法を重ねる | 方法の表の「事前の検討」の欄が空 |
| 止め方がなく、時間切れで止まる | 根に期限と未達時の報告の形がない |

## 他のスキルとの境界

- 方法や規模が過剰か、方向がずれていないか → metalize
- 個々の主張が正しいか → adversarial-review
- 言葉と文体 → ja-review(木を報告にする前に実行する)
