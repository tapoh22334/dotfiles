# 商品一覧のキャッシュ設計

## 背景

商品一覧 API の応答は平均 800ms かかっている。応答の 9 割は DB への問い合わせである。商品データの更新は 1 日に数回しかない。

## 方式

商品一覧の応答を Redis に保存し、同じ条件の要求には保存した応答を返す。キーは検索条件のハッシュとする。

## 無効化

キャッシュの無効化については色々と検討したのですが、商品の更新のたびに関連するキーを特定して消す方式だと、検索条件の組み合わせが多いためにどのキーが影響を受けるかを正確に求めるのが難しく、消し漏れが起きると古い価格が表示されてしまうという問題があるので、それよりは多少キャッシュの効率が落ちるとしても、商品が 1 件でも更新されたら一覧のキャッシュを全部消すという単純な方式のほうが安全だと判断しました。

## 監視

キャッシュのヒット率を Prometheus に送る。
