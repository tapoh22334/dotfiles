# Session Close (Safe) — 他のセッションを壊さずに畳む

散らかってきたセッションを閉じたい。だがこの機械では、いま**他のセッションも
同時に動いている**かもしれない。別のワークツリーで誰か(未来/並行の自分)が
デバッグ中で、共有ブランチにコミットが積まれ、設定ファイルが書き換わっている
最中かもしれない。ここで無造作に `git add -A` してコミットし、`git push -f`
すると、**自分の片付けが他人の作業を巻き込んで壊す**。

このスキルの仕事は、**共有された机の上で、自分の書類だけを片付けて席を立つ**
こと。片付ける前に一つだけ問い続ける:**「いま触ろうとしているこの変更・
ブランチ・記録先は、本当に"このセッションのもの"か?」**。所有が確かめられた
ものだけを畳み、確かめられないものには手を出さない。

記録の中身(何を残し何を捨てるか)と畳み方の作法は `backlog-suspend` と同じ
思想に立つ — このスキルはその手前に**並行性の関門**を足したものだ。純粋に
1セッションしか無いと分かっているなら `backlog-suspend` で足りる。他が動いて
いる**かもしれない**なら、こちらを使う。

## なぜ「所有の確認」が先に来るのか

普通のセッション終いは「キリのいい状態を作る → 記録する → 報告する」の三段だ。
だが並行環境では、その各段が他セッションを壊しうる:

- **コミット**が、他セッションの未コミット変更や無関係なゴミまで巻き込む。
- **push/rebase/force** が、他セッションが積んだ共有ブランチのコミットを飛ばす。
- **記録の書き込み**が、他セッションが同じ Backlog タスク/issue に書いた文脈を
  上書きする。

だから三段の**前に関門を置く**。関門を通ったものだけが、以降の操作の対象になる。

## 関門 — 畳む前に所有を確かめる

順に確かめる。ここは読み取りだけで、まだ何も変更しない。

### G1. 自分のワークツリーの居場所を知る

まず全体像を撮る。`git worktree list` は、この機械で**いくつのセッションが
どこで何のブランチを触っているか**を一覧にする。自分がいるのはどれか(cwd)、
他にいくつ生きているかを把握する。

```
git worktree list
git rev-parse --show-toplevel     # 自分のワークツリーの root
git branch --show-current          # 自分のブランチ(detached なら空)
```

ワークツリーが**セッション境界**になっている環境では、「自分のもの」= 自分の
ワークツリー root 配下、が第一近似になる。以降の片付けは**この root の外に
出ない**。他のワークツリーのパスに触る操作は、たとえ同じリポジトリでも
「他人の机」だと考える。

### G2. 未コミット変更の"帰属"を仕分ける

`git status` の未コミット変更が全部自分のものとは限らない。共有ワークツリー
では、**自分がこのセッションで実際に編集したファイル**と、以前から居座る
ゴミ・他の作業の残骸・生成物が混在する。

```
git status --short
```

各エントリを三つに仕分ける:

- **自分がこのセッションで編集したもの** → 畳む対象(コミット候補)。
  会話の履歴(このセッションで自分が Edit/Write したファイル)が一次証拠。
  記憶が曖昧なら `git diff -- <path>` で中身を見て、自分の作業か判断する。
- **無関係なノイズ**(`?? dist-windows/`、`?? .superpowers/`、ビルド生成物、
  別作業の scratch) → **触らない**。コミットに含めない。消さない
  (他セッションのものかもしれない)。
- **帰属が判断できないもの** → **触らない**。迷ったら残す。片付けの目的は
  自分の成果を失わないことであって、机全体を掃除することではない。

**`git add -A` / `git add .` を使わない。** これが並行環境で最も事故る操作。
畳む対象と決めたファイルだけを**名前を挙げて** `git add <path>...` する。
仕分けの結果「自分の変更はこの3ファイル」と言えるまで、コミットに進まない。

### G3. ブランチ・記録先が競合しないか確かめる

コミット先のブランチと、文脈の記録先(Backlog タスク/issue)が、他セッションと
ぶつからないか。

- **ブランチ**: 自分のワークツリーが専有するブランチ(`git worktree list` で
  他に同名が出ない)なら、コミット/push は安全。**detached HEAD** なら、
  勝手に既存ブランチへ載せない — 名前を確認してから。**共有されうるブランチ
  (main 等)** への push/merge/force は G の対象外、後述の「破壊的操作」へ。
- **push 前に上流を確認**: `git fetch` してから、自分のローカルが上流の先に
  あるか(fast-forward で押せるか)を見る。上流が進んでいたら、他セッション
  (か CI)が動かした可能性 → **force で潰さない**。追いつけないなら push は
  保留し、そのことを記録に残して離脱する(競合解決は畳む作業ではない)。
- **記録先**: Backlog タスク/issue に書く前に、他セッションが直近で同じ場所を
  更新していないか一瞥する(`backlog task <id> --plain` / issue の最終更新)。
  上書きではなく**追記**する。同じタスクに複数セッションが書くなら、自分の
  セッションが分かる一行(何のワークツリー/ブランチか)を添えて混線を防ぐ。

関門を通過したら、以下の三段に進む。中身の判断基準は `backlog-suspend` と共通
なので要点だけ示す。

## 畳む三段(関門を通ったものだけ)

### 1. キリのいい状態を作る

G2 で名指しした自分のファイルだけを、意味のある単位で `git add <path>` →
コミット。デフォルトブランチ上なら先にブランチを切る。コミット済み未 push は
G3 の fast-forward 確認を経て push。レビューに値する差分なら draft PR まで。

安全(取り消せる・前進のみ)な操作は確認不要で進める。

### 2. 失うと痛い文脈だけ記録する

原則は `backlog-suspend` と同じ:**再現困難なものだけ残し、容易に再現できる
ものは捨てる**。残すのは頭の中にしかないもの — レビュー/デバッグの現在地
(立てた仮説と根拠、次に疑う場所)、方針を選んだ理由、次の一手とその狙い。
捨てるのは git log で辿れる履歴、コマンド一つで再現する手順、一般論。

**位置ではなく意味を書く。**「◯行目まで確認」ではなく「◯を見てこう判断、
残る懸念はここ、次はこれを確かめる」。行番号は git にある。復元できない
頭の中身を残す。記録先は G3 で競合を確認済みの場所へ**追記**する。

### 3. 閉じられる状態を報告する

短く:何をキリのいい地点まで運んだか(push URL / PR)、どの記録先に何を
書いたか、**あえて触らなかったもの**(「`dist-windows/` は帰属不明のため
残置」「上流が進んでいたため push 保留」)、次に開くとき最初に見る場所。

「触らなかったもの」の明示が、このスキルでは特に重要 — それが「他を壊して
いない」ことの証明になる。

## Backlog 連携(この環境)

このプロジェクトは Backlog.md(`backlog` CLI)でタスクを管理する。記録は必ず
`backlog` CLI 経由(task md の直接編集はメタデータ整合を壊す)。記録の直前に
`backlog instructions task-execution` を読む。Backlog が無いプロジェクトでは、
記録先をコミットメッセージ/PR 本文に厚めに書き、新規ファイルは作らない。

## やってはいけないこと

- **`git add -A` / `git add .`**:並行環境で最悪の一手。他の未コミット変更や
  ノイズを巻き込む。畳む対象は必ず名指しで add する。
- **上流を見ずに push / force push**:他セッションや CI が積んだコミットを飛ばす。
  fetch して fast-forward を確かめる。追いつけないなら push を保留して記録する。
- **帰属不明ファイルの削除/コミット**:他セッションのものかもしれない。残す。
- **記録先の上書き**:同じタスク/issue を他セッションが更新済みかも。追記し、
  自分のセッションが分かる一行を添える。
- **自分のワークツリー root の外に出る操作**:他のワークツリーのパスに触る、
  他ブランチを載せ替える。それは他人の机。
- **確認なしの破壊的操作**:main への merge、force push、削除、外部への公開。
  取り消せない操作は必ず止まって確認する。
- **過剰記録・机全体の掃除**:目的は自分の成果を失わないこと。共有の散らかりを
  全部片付けようとしない — かえって他を壊す。
