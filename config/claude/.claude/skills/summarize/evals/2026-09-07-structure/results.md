# 対照実験: 散文固定 vs 見出し付きセクション (2026-09-07)

**素材**: session-fixture.md（ma-splitflap 実セッションの事実のみ、文体は含まない）
**方法**: 各アームの指示文を新鮮なサブエージェントに与え、5回ずつ要約を生成。
無誘導の対照群は不要（Aが現行スキルそのものであり、これが対照群にあたる）。

## アーム
- **A = 現行文面**: "2–4 short paragraphs in prose" + 見出し/箇条書きの禁止
  + "Anchor claims to concrete artifacts — file paths, function names, commit hashes"
- **B = 候補文面**: arm-B-candidate.md（意味を名指す見出し2–4個、1段落200字上限、
  意味論優先で識別子は「読者が行動/検証に使うとき」だけ）

## 判定

**採用（B）。** 差は明確かつ全runで一貫:
- A は 5/5 が見出しゼロ・400字超の壁。現行文面は壁を確実に生産している。
- B は 5/5 が「意味を名指す見出し＋200字以内」に収束。分散が小さく、文面が縛れている。
- B は識別子を意味に言い換えつつ（sound_events →「Rust側のイベント」、
  DISPLAY →「マシンの表示先設定が到達不能なX11転送先」）、
  **決定的な数値 848→170 / 96発/100ms は 5/5 で保持**。意図どおり。

## 副次観察

- B は箇条書きを「3つの選択肢」にだけ使い、地の文はプロースのまま。
  「peer items のときだけリスト」という条件が機能している。
- B の見出しは "概要" のような無内容ラベルにならず、
  「効いていなかった部分」「直っていない本丸」など**結論を名指す**傾向。
  これは指示の "The heading names the meaning of the block" が効いた結果。
