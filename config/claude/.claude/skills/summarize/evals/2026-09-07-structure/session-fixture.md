# 実験素材: 実セッションの事実（要約対象）

このファイルは対照実験用の固定入力。ma-splitflap プロジェクトの実セッション
(6329b45a, 2026-07-25〜09-07) の事実だけを列挙したもの。文体は含めない。

## 依頼
ボードサイズが変わるときのトランジションが不快。急に切り替わり、フラップ全部が
一瞬「ザッ」と鳴る。これをいいかんじのUXにしたい。

## 設計で決めたこと（と理由）
- 物理的連続性を採用。盤面を一つの装置として扱い、残せるセルは文字を保つ。
  演出的に一度クリアする案は却下（装置の同一性が切れるため）。
- 空間写像は中央アンカー。clip_frame が既にそうなっていたので踏襲。
- 一斉フリップ対策はエンジン側スタガー。音側パッチではなく動きの帰結として
  音が分散する形を選んだ。
- 掃き出しは列ウェーブ。音の分散とパンニングが既に列位置基準のため、視覚を
  同じ軸に揃えた。
- ユーザー指摘「大きいボードだとフラップのサイズが変わるのは考慮できている?」
  → 設計の穴だった。セル寸法は列数の従属変数。スイープを1tick遅らせ
  「箱が組み変わる」→「文字が入れ替わる」の二段に分けた。

## 実装
- ブランチ feat-board-transition、8コミット。
- 異寸法パスが全セルを Blank にリセットしていたためグリフ保存が働かなかった
  点を修正。中央アンカー式は共有化して二重実装を防いだ。
- スタガーは Board が保持、Driver は無関知（プロジェクトのDriver純粋性規約）。
- 途中で stall バグを自分で発見（フレームが来ないと永久に armed）。expire 処理を追加。
- Rust 302テスト、E2E chromium 77/77、WebKit 39/39 通過。

## 判明した重大な問題
- ユーザーが実機で「変わってないようにみえる」と指摘 → 正しかった。
- 実音を計測すると総発音数は 848→170 (-80%) だが、ピークは 96発/100ms のまま不変。
- 原因: 発音は Rust の sound_events ではなくフロントが文字変化を観測した瞬間に鳴る。
  sound_events はフロントで未使用。Rustユニットテストで測った「ピーク576→240」は
  実際の音とは別経路の数字だった。テストは通っていたが測る対象を間違えていた。

## 回り道（環境要因）
- E2Eが延々失敗 → 原因はコードでなくマシンの DISPLAY=localhost:10.0（到達不能な
  X11転送先）。DISPLAY=:99 で 1時間超・失敗あり → 3.4分・全通過。
- WebKitの1件を一度「本物のリグレッション」と報告したが再現せず、誤りだった。
